- Стенд `tests/bot/harness.py`: настоящие обработчики на поддельной сессии Telegram (сообщения, кнопки, геопозиция, повтор апдейта, группа); доставка уведомлений через настоящий диспетчер.
- Найдено и исправлено при проверке: потеря покрытия из-за greenlet (включён `concurrency = greenlet`); недостижимая ветка в `describe_rule`.

### Соглашения этапа 3

- Один транзакционный `UnitOfWork` на апдейт; исключение откатывает всё, включая запись о дедупликации (повтор апдейта обработается). Для SQLite это держит блокировку записи на время ответа в Telegram — SQLite только для разработки.
- Чужой и несуществующий `id` неразличимы для пользователя (одинаковый ответ).
- Обработчики используют общий `Ctx` (ответ, FSM, зависимости, транзакция, пользователь).
- Роутеры подключаются копиями (`_fresh`): aiogram позволяет подключить роутер только к одному диспетчеру.
- Удаление напоминания — сразу, с кнопкой «Вернуть» (без подтверждения).
- `nag` («настойчиво») сохраняется в напоминании, но повторы доставки реализуются на этапе 4 (S5); пользователю это пока не обещается.

## Этап 1 — сделано

- `domain`: `local_to_utc`/`utc_to_local` (DST: пропущенное время → момент перехода, повтор → первое вхождение), `Recurrence`/`Schedule`/`next_occurrence`/`occurrences`, (де)сериализация RRULE. DAILY/WEEKLY — `dateutil.rrule`; MONTHLY/YEARLY — собственный генератор (зажим «31-го» к последнему дню, 29 февраля → 28); MINUTELY/HOURLY — арифметика в UTC.
- `nlp`: нормализация с сохранением позиций, токенизатор, матчеры (относительное время, даты, дни недели, часы с фильтром ложных «в 5 магазинов», «половина десятого», «без пятнадцати три», повторы, лимиты, «за час до», `важно`, категории), разрешение конфликтов по приоритету, вычисление первого вхождения, очистка текста, нечёткое сопоставление категорий (`rapidfuzz`), подсказки по словарю/истории, CLI-песочница.
- Корпус `tests/unit/nlp/corpus.py` (187 кейсов), property- и fuzz-тесты (произвольный Unicode, «словесный салат», adversarial-вход), бюджет p95 < 20 мс на 200 символов.
- Найдено fuzz-тестом и исправлено: `pymorphy3` падает на буквах без имени в Unicode — морфология теперь вызывается только для кириллицы/латиницы.

### Соглашения парсера (ТЗ неоднозначно — зафиксировано)

- «Сейчас» + 1 минута — порог «в будущем»; `в 15:00` при `now` = 15:00 → завтра.
- Неоднозначный час (`в 6`): варианты h и h+12 в окне 07:00–23:00, берётся ближайший будущий (флаг `ambiguous_hour`). Для повторов — привычное чтение: 7–11 утро, 12 полдень, 1–6 после полудня.
- `HH:MM`, часы ≥ 13, `0` и «час + часть суток» однозначны. Дата без времени → якорь «утро» (флаг `time_inferred`); «сегодня» без времени при уже прошедшем якоре → вопрос (`needs_time`); явная дата/время в прошлом → отказ (`past_date`).
- «в следующий <день недели>» = этот день в следующей календарной неделе (пн–вс); «в эту <день>» — ближайший в текущей неделе.
- `через неделю/месяц` без времени → 09:00 (якорь «утро»); `через N минут/часов` — точное смещение от «сейчас».
- Дата без года — ближайшая будущая; 29 февраля — ближайший високосный год.
- `за N минут/часов` — «заранее» и без «до»; `за N дней/недель` — только с «до» (иначе «заплатить за неделю» ложно срабатывает).
- «за N до <событие>» (после «до» дата, время, день недели или «новый год») — это один момент `событие − N`: напоминание сдвигается назад, «заранее» не добавляется. Если после «до» ничего нет («завтра в 18:00 встреча за час до») — прежнее поведение: событие + предуведомление. «Новый год» = 1 января 00:00, распознаётся только с «на/до/к» («с новым годом» — не дата).
- Если после «до» не событие, а обычные слова («за час до работы», «до 5 кг»), «до» остаётся в тексте напоминания, а смещение — обычное «заранее». «заранее за N дней» / «предупреди за N дней» — «заранее» и без «до». Для смещений в целые дни от «нового года» время — утренний якорь (09:00), для часов — отсчёт от 00:00.
- «N числа» / «N-го» без месяца — ближайшее такое число (в этом или следующем месяце); сегодняшнее число с прошедшим временем — вопрос (`needs_time` / `past_date`), а не тихий перенос на месяц. «каждый месяц N числа» → `BYMONTHDAY=N`. «до 18:00», «до пятницы», «до завтра» — срок: напоминание в этот момент. «с утра» — утренний якорь, «через полгода» — 6 месяцев.
- «на следующей/этой неделе» с днём недели (до или после него) задаёт неделю; «ближайший <день>» — как без уточнения. Время словами и «в 8 30» / «в 20 00» / «в 9ч 30м» — часы и минуты; «в пол девятого» = 8:30; «ровно/примерно/около» не попадают в текст. «через часик/1,5 часа/часа два/час сорок» — смещения; уменьшительные («минутку», «денёк») понимаются.
- Неточные части суток («после обеда», «перед обедом», «после работы», «рано утром», «поздно вечером», «ночью», «на ночь») дают предложенное время с флагом `time_uncertain` — бот просит подтвердить, а не молча ставит 09:00; «утречком/вечерком/к вечеру» — обычные якоря. Несколько частей суток в одной фразе («утром и вечером») — вопрос (`multiple_times`): одно напоминание — одно время.
- Повторы: «в будни / в будние дни» = каждый будний день; «в течение N <ед.>» / «на протяжении …» → `UNTIL` от первого вхождения; «по <дата>» — включительный конец; «с <дата/дня недели>», «с завтрашнего дня», «со следующей недели» — начало серии. «В последнюю пятницу месяца» (n-й день недели месяца) распознаётся, но правила повтора для него нет — бот спрашивает «когда», а не угадывает дату.
- Порог уверенности `CONFIDENCE_THRESHOLD = 0.7`; потолки по флагам — в `resolver.FLAG_CAPS`.

## Что осталось

**До запуска для людей (обязательно)**

1. **Проверить сборку Docker.** `Dockerfile`, `docker-compose.yml`, `docs/DEPLOY.md` и healthcheck написаны, но **образ не собирался и compose не запускался** (в среде разработки нет Docker). Косвенно проверено: compose-файл разбирается, все файлы из `COPY` существуют, набор production-зависимостей (`uv sync --no-dev`) полон, миграции и запуск процесса работают в таком окружении, остановка по SIGTERM занимает < 1 с. Версия `uv` в Dockerfile (0.11) соответствует той, что собрала `uv.lock`.
2. **Живой прогон.** Реальный токен, реальный Telegram: первые минуты почти наверняка вскроют мелочи, которых не видно на поддельной сессии (HTML-форматирование, лимиты Telegram, поведение кнопок на телефоне).
3. **Запуск CI** в настоящем репозитории (workflow написан, но не выполнялся).
4. **Режим webhook** (параметры в конфиге есть, запуск не подключён) — нужен только если не подходит long polling.
5. **Финальная верификация по чек-листу ТЗ** (раздел 13) и дымовой тест на чистом сервере.

**Желательные функции (SHOULD), не реализованы**

- **S5 «настойчиво»**: флаг сохраняется при создании, но повторные напоминания до отметки не отправляются (нужна доработка диспетчера и групповая отметка вхождения; заготовка репозитория `ack_group`/`unack_group` уже есть).
- **Адаптивное откладывание** (варианты зависят от времени суток) — сейчас фиксированный набор.
- **S1** ответ на уведомление/карточку («готово», «через час»).
- **S3** утренняя сводка (поля пользователя и вид уведомления `digest` готовы, планировщика нет).
- **S6** правка исходного сообщения обновляет напоминание.
- **S7** «добавить сюда» из экрана категории.
- **S11** опциональный LLM-разбор (в конфиге есть флаги, реализации нет).

**Известные ограничения**

- SQLite годится только для разработки: транзакция на апдейт держит блокировку записи на время ответа в Telegram.
- Троттлинг хранится в памяти процесса (при нескольких экземплярах лимит на каждый отдельно).
- Тяжёлые зависимости определения пояса (~300 МБ на диске, ~120 МБ RAM) — см. ADR-0008.
