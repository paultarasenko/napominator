# ADR-0006: Политика времени и DST

**Статус:** принято · 13.10.2026

**Решение.**
1. В БД только UTC; наивные `datetime` в домене запрещены (ruff `DTZ`), исключение — явно названные `*_local`.
2. «Сейчас» — только через внедряемый `Clock`.
3. Повторы — по локальному настенному времени: `rrule` над наивным `dtstart_local`, затем локализация `zoneinfo`.
4. Пропущенный час (переход вперёд) → первый допустимый момент после скачка; повторяющийся час → первое вхождение (`fold=0`); одно локальное вхождение не срабатывает дважды.
5. «Каждое 31-е» в коротких месяцах → последний день; 29 февраля в невисокосные годы → 28 февраля.

**Проверка.** Property-тесты (`hypothesis`) и DST-кейсы на `Europe/Berlin`, `America/New_York`, `Australia/Lord_Howe` (сдвиг 30 минут).

**Реализация.** `dateutil.rrule` применяется только для DAILY/WEEKLY. MONTHLY/YEARLY реализованы явным генератором, потому что RFC 5545 *пропускает* месяцы без 31-го, а продуктовое правило — зажим к последнему дню; MINUTELY/HOURLY считаются в UTC. Горизонт — 10 лет от момента запроса.
