# ADR-0008: Определение часового пояса офлайн и вес зависимостей

**Статус:** принято · 15.10.2026

**Контекст.** Нужен часовой пояс пользователя тремя способами: геопозиция, название города, список. Данные о местоположении чувствительны, внешние сервисы нежелательны.

**Решение.** `timezonefinder` (координаты → IANA) и `geonamescache` (город → пояс; русские названия есть в `alternatenames`), оба офлайн. Координаты используются один раз для определения пояса и не сохраняются и не логируются (тест проверяет, что их нет в переписке). Город ищется точно, затем с допуском опечаток (`rapidfuzz`, порог 84); при равенстве названий побеждает самый населённый город. Результат всегда подтверждается вопросом «у тебя сейчас HH:MM?».

**Стоимость (измерено).** Установка ≈ 300 МБ на диске (179 МБ — данные `geonamescache`), ≈ 106–125 МБ RSS при индексе городов с населением от 15 000 (≈ 206 тыс. ключей), инициализация ≈ 1 с, нечёткий поиск 100–200 мс. Допустимо для VPS 1 vCPU / 1 ГБ: индекс строится лениво при первом онбординге и ищется в отдельном потоке (`asyncio.to_thread`), чтобы не блокировать цикл событий.

**Отвергнуто.** Внешние геокодеры (утечка данных, зависимость от сети); только список поясов (хуже UX для «Новосибирска», «Алматы» и т. п.).

**Последствия.** Образ Docker заметно тяжелее базового; при необходимости можно поднять порог населения или оставить только русскоязычные ключи.
